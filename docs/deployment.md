# 자동 배포

사용 목표: GitHub 배포 브랜치에 push → 자동 테스트 → 성공한 코드만 서버에 배포 → 새 버전의 Slack 봇 실행.

## 공통 준비

`.github/workflows/checks.yml`은 push와 PR에서 Python 3.12 테스트·구문·의존성을 검증한다. 테스트에는 실제 API 키와 유료 모델 호출이 필요하지 않다. 테스트 실패 커밋은 배포하지 않는다.

실행 명령은 `python app.py slack`이다. Socket Mode를 사용하므로 외부에서 접속하는 웹 주소나 HTTP 포트는 필요하지 않다. 프로세스가 계속 실행될 호스팅이 필요하다.

서버에는 ANTHROPIC_API_KEY, SLACK_BOT_TOKEN, SLACK_APP_TOKEN을 비밀 환경변수로 저장한다. 일반 설정은 CLAUDE_MODEL, BOT_MODE=documents, BOT_DB다. 키를 Git에 넣지 않는다.

SQLite 파일은 배포할 때 지워지지 않는 영구 볼륨에 둔다. 로컬 data/는 자동 업로드되지 않는다. 초기 자료 입력과 DB 이전은 호스팅 연결 후 별도 확인한다. 단일 인스턴스로 운영한다.

Dockerfile도 제공한다. 컨테이너는 일반 사용자로 실행하고 /data를 영구 볼륨으로 연결한다. 빌드 컨텍스트는 .dockerignore 허용 목록의 코드만 포함하므로 로컬 키와 DB를 이미지에 넣지 않는다. 현재 로컬 환경에는 Docker가 없어 이미지 빌드는 아직 검증하지 않았다. GitHub CI에서 이미지 빌드를 검증한다.

코드뿐 아니라 환경변수와 자료 상태도 실행 결과에 영향을 준다. API 연결 코드를 배포해도 키와 자료를 설정하지 않으면 해당 기능은 동작하지 않는다. 현재 DART·증권사 API, Slack 자료 수집·GitHub 원문 저장은 미구현이다.

## 배포 완료 확인 기준

1. GitHub에서 자동 테스트 성공을 확인한다.
2. 서버에 배포된 커밋이 push한 커밋과 같은지 확인한다.
3. 봇의 Socket Mode 연결 성공을 확인한다.
4. 배포 후에도 기존 DB 자료와 분석 기록이 유지되는지 확인한다.
5. Slack 실제 응답 검증은 별도로 수행한다. 배포 확인만으로 Claude 유료 호출을 실행하지 않는다.

## 현재 상태

로컬에서 배포 준비 중이다. 호스팅과 배포 브랜치 연결, 서버의 비밀 환경변수, 영구 볼륨, 첫 배포는 아직 설정되지 않았다. 자동 배포가 활성화되었다고 판단할 수 있는 상태는 아니다.
