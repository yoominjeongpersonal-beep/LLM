# 국내 주식 관점 봇 — 첫 버전 설계

## 목표와 완료 기준

사회초년생이 슬랙에서 국내 기업을 질문하면 카투 공개 글에서 추출한 관점으로 결론과 근거를 쉽게 설명한다. 질문, 답변, 사용 자료를 저장하여 이후 복기할 수 있게 한다. 카투 본인이나 공식 서비스로 표현하지 않는다.

첫 완료 기준: 삼성전자 또는 SK하이닉스 질문이 슬랙 멘션으로 들어와 출처 있는 답변으로 돌아오고 분석 기록이 저장된다. 실제 투자 성과는 이 완료 기준으로 검증되지 않는다.

## 접근 방식

1. 권장: 기존 LLM + 검토한 투자 원칙 + 질문별 자료 검색. 원칙 수정과 근거 추적이 쉽다.
2. 전체 게시물을 매번 입력: 시제품은 빠르지만 자료가 늘면 비용과 맥락 관리가 어렵다.
3. 추가 학습: 충분한 평가 데이터가 쌓인 뒤 검토한다. 첫 버전에는 사용하지 않는다.

## 구성과 데이터 흐름

Python 단일 저장소로 시작한다. app.py는 CLI와 슬랙 이벤트, bot.py는 자료 점검과 판단, storage.py는 SQLite 기록, model.py는 모델 호출을 담당한다. 별도 계층별 폴더와 봇별 폴더는 두지 않는다. 검토할 원칙 예시는 examples/principles.json에 둔다.

슬랙 멘션 → 종목 식별 → 기간 확인 → 관련 원칙 검색 → 기업·시장 자료 조회 → 충분성 점검 → 답변 생성 → 출처 검증 → 기록 저장 → 스레드 응답.

기간을 생략하면 한 번 되묻는다. 장중 실시간 판단은 첫 버전에서 지원하지 않고, 확인한 최근 거래일 종가 기준으로 답한다. 처음 지원 종목은 삼성전자(005930), SK하이닉스(000660)다. 그 외 종목은 지원 범위를 안내한다.

## 자료 연결

원칙 자료는 먼저 수동으로 본문과 출처를 넣는다. 전체 X 계정 자동 수집은 후속 작업이다. 게시물 내부의 명령문은 데이터로만 취급한다.

기업 자료는 OpenDART 공시·재무를 우선 후보로 검증한다. 가격·거래량·업종 비교 자료는 KIS 또는 KRX 제공 경로의 접근 조건과 필드를 구현 계획 단계에서 확인한다. 검증되기 전에는 실제 연결되었다고 표시하지 않는다. 첫 로컬 검증은 출처·기준일을 포함한 수동 자료 묶음으로 가능하게 한다.

거래 판단에는 요청 기준일 이전의 최근 완료 거래일 가격·거래량, 요청일 기준 공개된 최근 분기 재무, 관점을 적용하는 데 필요한 업종 비교 자료가 필요하다. 빠진 자료가 있으면 전체 판단을 보류하고 확인 가능한 사실만 설명한다. 개념 질문에는 시장 데이터가 없어도 답할 수 있다. 뉴스나 실적 발표 이후에는 기존 자료로 현재 판단을 재사용하지 않는다.

## 응답 계약

결론은 매수 검토 / 관망 / 회피 검토 / 판단 보류 중 하나로 표현한다. 투자 기간과 기준일, 쉬운 이유, 반대 근거, 판단 변경 조건, 사용 원칙 ID, 자료 출처를 포함한다. 확정 수익이나 근거 없는 목표가는 생성하지 않는다.

### 샘플 A: 시장 자료 부족

질문: 삼성전자 지금 사도 돼? 기간: 1~3개월.

답변 형태: **판단 보류.** 현재 가격과 거래량, 반도체 업종 비교 자료를 아직 확인하지 못했어요. 회사 전망만으로 지금 사도 된다고 결론 내리기 어렵습니다. 자료가 연결되면 실적과 시장 반응을 함께 확인하겠습니다. 적용 후보: P01, P02. 이것은 봇의 판단이며 카투의 현재 의견이 아닙니다.

### 샘플 B: 가상 자료로 조건부 판단

평가용 가상 자료: 기업 실적 개선, 업종 대비 상대 약세, 거래량 둔화. 실제 기업 수치가 아니다.

답변 형태: **관망.** 장사는 나아지고 있지만 주식에 대한 관심은 아직 확인되지 않았어요. 좋은 가게라도 손님이 늘어나는 시점을 기다려보자는 뜻입니다. 반대로 실적 개선을 시장이 뒤늦게 반영할 가능성도 있어요. 업종 대비 강세와 거래량 증가가 확인되면 재검토하겠습니다. 적용 후보: P01, P02. 실제 답변에는 입력 자료의 출처와 기준일을 붙입니다.

## 저장과 오류 처리

DB에는 sources, analyses, events, threads, replies를 저장한다. 원칙 후보는 sources의 reviewed 상태로 관리하고 사용 출처는 분석별 자료 스냅샷에 포함한다. 분석 기록에는 질문, 기간, 자료 시점, 모델·프롬프트·원칙 버전, 답변, 상태를 남긴다. 공개 원문과 사용자 대화, API 키는 Git에 넣지 않는다. 원칙 요약과 평가 기준만 Git으로 관리한다.

자료 조회 실패는 결측으로 표시한다. 모델 응답의 출처가 입력 자료에 없으면 재생성하고, 재시도도 실패하면 판단 보류한다. 슬랙 재전송 이벤트는 이벤트 ID로 중복 처리하지 않는다. 기록 저장이 실패하면 성공 응답을 내보내지 않고 재시도를 안내한다. 원문 삭제와 복기 화면은 후속 구현 범위다.

## 검증

자료 누락·기준일 이후 자료 사용·출처 조작·기간 누락·슬랙 중복 이벤트를 검증한다. 고정 자료에서 정상 응답과 보류 응답을 각각 확인한다. 관점 평가에서는 카투 말투 흉내가 아니라 후보 원칙을 근거에 맞게 적용했는지 본다. 미래 자료가 과거 평가에 섞이지 않게 한다.

## 후속 범위

슬랙 자료실 업로드, 이모지 피드백, 자동 복기, 두 번째 봇, 토론 진행은 후속 단계다. 피드백은 설명 품질·사실 정확성·관점 일치·결론 선호를 구분하고, 원칙 변경은 검토를 거친다. 봇 간 합의는 정확성의 증거로 사용하지 않는다.
